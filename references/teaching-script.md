# 教学讲稿流程(文章/教程 → 白板讲解视频)

> 输入是一篇文章/教程/文档,要产出"把它讲透"的视频时,**优先走本流程**。
> 来源:UART 教程视频项目复盘(对照原文逐项覆盖、问题驱动、先稿后片)。
>
> **硬性**:用户确认闸门见 [`user-gates.md`](user-gates.md)。未过 G1/G2/G3,不得绘图、配音、渲染。

## 核心原则(踩坑总结,违反必返工)

1. **先稿后片 + 先确认后制作**:讲稿是第一交付物。逐拍表格写进 `讲稿.md`,自检通过后**必须停下来让用户确认讲稿(G2)**,用户明确同意才动笔画图。禁止边画边想,禁止一路干到底。
2. **风格先选再写**:写完整讲稿前先让用户选讲稿风格(G1)。默认推荐**一问一答**(问/答分 region),不要默认独白。
3. **问题驱动,拒绝照书念**:开场用真实实验/悬念提问;每个概念必须由一个具体问题引出(白板上画 Q 气泡,先问再答);结尾回扣开头的问题,让观众自己能答上来。
4. **举例 ≠ 比喻**:受众高中生及以上时,例子要用真材料——数值计算、真实编码/帧实例、失配实验、原理与局限。比喻只作一句话辅助,不许当骨架。
5. **原文覆盖度优先**:逐项盘点原文知识点列成清单,制作前逐项打勾;不许因为"不好画"就漏讲。
6. **原文图片是知识的一部分**:全部下载并逐张 Read 理解。照片/截图/接线图直接合成上屏(当作贴在白板上的原文图表);数据帧、连接图等示意图按原文结构忠实重绘;blob 等无法下载的图按内容重绘。
7. **每讲找 1~2 个启发点**:解释"为什么这样设计"而不是"是什么"。例:UART 起始位 = 每字节开头重新对表,时钟误差不累积,所以敢省掉时钟线。这是"让人有启发"的关键。
8. **音色用户选**:不得默认塞 `Yunxi`/`Xiaoyi` 就开跑 TTS。过 G3 后再配音。

## 流程(含确认闸)

| 步 | 做什么 | 要点 |
|---|---|---|
| 0 | 任务规格(G0) | 画幅、目标时长、是否系列;用户确认或明确「用默认」 |
| 1 | 全文抓取 | web_reader 抓正文 + 图片清单;下载全部可访问图片,逐张 Read 理解;记录 blob 图并按内容重绘 |
| 2 | 知识点盘点 | 列覆盖度清单:定义/原理/参数/帧或协议结构/代码逐行/硬件与接线/坑与限制/图片 |
| 3 | 讲稿风格(G1) | **停**:贴风格选项(一问一答推荐 / 独白 / 苏格拉底)。用户选定后再写稿 |
| 4 | 写 `讲稿.md` | 按选定风格写逐拍表;一问一答须有角色列或「问：/答：」前缀;例子数值自己算一遍 |
| 5 | 讲稿自检 + 内容确认(G2) | 自检勾选后**停**,把讲稿与清单交给用户。用户说「讲稿确认/可以画」才进入下一步 |
| 6 | 绘图脚本 | 固定模式:Q 气泡(qbubble)、代码卡(代码+大白话注释同行)、实例条(格子逐位)、真实图 paste_fig;bx() 一律像素 (x0,y0,x1,y1) |
| 7 | TTS 语音确认(G3) | **停**:按 `user-gates.md` 单独获准后探测或试听,贴音色与语速选项;用户选定后写入 plan 再批量配音 |
| 8 | 音频 | 按 G3 的 voice/rate;快速版在加工端裁分片首尾静音;gap 0.2。**技术/编程内容:内置配音在 TTS 输入端自动把 `_` 转成空格(text_version);自定义 TTS 程序必须自行做同样处理** |
| 9 | 质检 + 冒烟(G4) | `check_assignment.py plan.json` 归属清零 → 渲一拍抽帧 → **停**等用户说可以全量 → 全量渲染 |
| 10 | 最终成片确认(G5) | 技术质检后提交完整视频、检查结果和已知问题;按 `user-gates.md` **停**等用户确认当前版本,再标记交付完成 |

## 语速与静音裁剪

使用内置快速版入口，不再用 monkey-patch 隐式覆盖已确认语速。把用户选定的 `rate` 和 `voice` 写入输入，再检查并确认有效配置：

```bash
python scripts/build_narration_fast.py plan.build.json --preflight
python scripts/user_gates.py --root . approve G3 --artifact plan.build.json --mode fast
python scripts/user_gates.py --root . confirm G3 --note "音色 1 + 快速版 +22%"
python scripts/build_narration_fast.py plan.build.json
```

快速版在加工音频时裁首尾静音，原始合成按实际语速单独缓存。改语速后重新确认 G3，由内容指纹决定重配，无须删除旧分片。
视频按输入与配置指纹复用；更改方案后重新生成样片并确认 G4。已有输出仅在用户明确选择 `--force` 时替换，历史运行保留。详细回执与教学计划见 [render-workflow.md](render-workflow.md)。

## 讲稿自检清单(附在 讲稿.md 末尾)

```
0. 闸门:G1 风格已由用户选定;本清单勾完后执行 G2(停,等用户确认),未确认不画板
1. 覆盖度:原文知识点逐项打勾(定义/原理/参数/结构/代码/硬件/坑/图片)
2. 准确性:例子里每个数值、编码、倍数自己重算一遍
3. 问题链:开场有问题;每个新概念前有问题;结尾回扣开头
4. 例子密度:真例子(计算/实例/实验)数 ≥ 知识点数的 1/3;比喻只作辅助
5. 启发点:≥1 个"为什么这样设计"
6. 节奏:单拍旁白 ≤50 字;预计总时长 = 拍数 × 4~5s(+15%~+25% 语速)
7. 风格落地:若选一问一答—问/答分 region、板上有 Q 气泡、旁白带角色前缀;不得写成纯独白
```

确认请求文案模板见 `user-gates.md` 的 G2 / G3 节。

## 常见错误(每条都真实踩过)

- **一路干到底**:未过 G1/G2/G3 就画板配音渲染 → 停,补确认闸;用户未豁免则返工到对应闸
- **照书念**:名词+定义罗列,无问题无例子 → 推倒重写,先补问题链
- **默认独白**:用户未选风格却写成一人讲 → 先补 G1;推荐改为一问一答
- **比喻幼稚化**:给高中生讲"嘴对耳朵"当主菜 → 换成计算/实例/原理
- **漏原文知识**:只挑好画的画 → 覆盖度清单逐项打勾
- **文字画在格子里被前一拍抢走**:值文字落在结构格所属 box 内 → 归属检查会抓到;把值文字单独成拍或调整 box
- **线缆端点距元素 <8px**:粘连成巨型组件 → 端点缩回留白缝
- **真实图与手绘元素重叠**:paste 的图要有独立白区;贴图后如需叠加文字,先目检
