日期：2026-10-17。
状态：任务草案 1–10 的应用层路径已实现。开发验证不等于真实配音、白板引擎绘制质量或最终人工观看验收。

初次规格整理范围：复审、离线复现与发布。后续实现操作见 [narration-workflow.md](narration-workflow.md) 与 [render-workflow.md](render-workflow.md)。

## Problem Statement

用户需要控制视频制作过程：先确认讲稿与音色，先看单拍样片，再决定是否全量渲染，最后确认完整成片。
但“有确认记录”还不等于“产物来自这次确认的输入”。
当前流程能够拦住缺少审批的入口，却没有闭合审批、缓存、实际执行参数和验收证据之间的关系。

复审发现以下用户可感知的问题：

1. 改了旁白或音色并重新确认后，旧音频仍会按相同文件名复用，视频说的不是新稿。
2. 改了画板、cue、主题或渲染质量后，旧分拍视频仍会复用，成片不是当前方案。
3. G4/G5 允许用任意非空文件录入确认，程序没有强制证明样片、完整视频或技术检查属于当前制作。
4. 单拍确认没有绑定完整的有效渲染配置；改变 CLI 参数或环境默认值后，缺少可靠的失效依据。
5. 归属检查仍是单独命令；默认渲染入口没有自动执行它，也没有消费其当前版本检查结果。
6. 媒体校验依赖仓库外的辅助技能，本地缺少该依赖时无法执行既定验收。
7. 现有自检主要检查文件存在和大小，不能证明时间窗中的绘制与旁白一致。
8. 教学内容需要明确“对象、关系、动作与结果”，并让练习停顿真正进入音轨；只有主题换色或画面延时不能满足这些需求。
9. 制作规则分布在多个文档，缺少关键文档承诺与实际行为一致性的回归检查。

这些问题不是防攻击需求。它们首先是正常迭代中的可靠性问题：
用户不应为了避免旧产物污染，每次手工删除音频、视频或猜测哪些检查执行过。
审核证据与离线复现结果见 Further Notes。

## Solution

保留现有白板引擎、region/cue 模型和 G0–G5 人工确认流程。
引入“有效配置、内容指纹、本次运行清单、结构化检查结果”四个机制，建立可验证的制作闭环。

用户体验：

1. 开始时只做本地环境预检，不自动发起配音、登录或收费请求。
2. 确认后的讲稿、音色、语速和实际制作参数形成有版本的输入快照。
3. 改稿时自动重配受影响的旁白；未变的旁白可以安全复用。
4. 改画板或渲染设置时，旧视频不会因为同名而被误用。
5. 全量渲染前展示当前版本的单拍样片、抽帧与检查结果。
6. 成片验收只认本次运行的产物和证据；未检查的项目明确显示未执行。
7. G5 同时要求当前完整视频、通过的必要技术检查，以及用户对该版本的确认。
8. 讲稿确认展示教学角色、画面形式和变化顺序；教学模式的思考停顿与音轨、cue 和帧数共同计算。

不把“全部改成 eggram”作为方案。借用它的运行隔离、缓存契约和验收原则，继续使用本项目的逐笔绘制与精确 cue。

## User Stories

以下故事使用指定的 As / I want / so that 格式，角色与需求用中文表达。

1. As a 视频制作者, I want 在制作前看到本地依赖缺口, so that 我不会到配音中途才发现无法出片。
2. As a 视频制作者, I want 预检不访问收费服务, so that 环境检查不会产生未授权费用。
3. As a 视频制作者, I want 保留 G0–G5 分阶段确认, so that 我能决定何时投入绘图、配音和全量渲染。
4. As a 视频制作者, I want 确认绑定实际生效的音色和语速, so that CLI 默认值不会改变我批准的方案。
5. As a 视频制作者, I want 改旁白后只重配受影响片段, so that 新稿正确且不浪费其余配音费用。
6. As a 视频制作者, I want 更换音色、模型或后端后自动使相关音频缓存失效, so that 成片使用正确的声音。
7. As a 视频制作者, I want 改语速或静音处理参数后重新加工相应音频, so that 节奏与确认内容一致。
8. As a 视频制作者, I want 缓存损坏或元数据缺失时拒绝复用, so that 中断运行不会污染后续产物。
9. As a 视频制作者, I want 重渲时安全复用未变的旁白, so that 换主题不会重复消耗 TTS。
10. As a 视频制作者, I want 改画板、cue 或时长后自动重渲受影响分拍, so that 旧画面不会混入新成片。
11. As a 视频制作者, I want 主题和质量参数参与视频缓存判定, so that 换皮或提高清晰度真的生效。
12. As a 视频制作者, I want 旧版无指纹的缓存不被默认信任, so that 升级后不会沿用来源不明的结果。
13. As a 视频制作者, I want 在配音前检查可静态发现的输入和画板问题, so that 错误不会先花掉配音成本。
14. As a 视频制作者, I want 渲染前自动检查组件归属与 cue 边界, so that 我不用记住额外的检查命令。
15. As a 视频制作者, I want 单拍样片明确属于当前完整方案, so that 我批准的是随后全量渲染的方案。
16. As a 视频制作者, I want 改变有效渲染配置后重新确认 G4, so that 未经确认的视觉变化不会直接出片。
17. As a 视频制作者, I want 每次运行有独立产物清单, so that 同名文件和不同主题不会互相混用。
18. As a 视频制作者, I want 看到本次生成和复用的真实数量, so that 我能核对成本与缓存行为。
19. As a 视频制作者, I want 缺少当前运行清单时验收失败, so that 检查不会猜测最近一次的产物。
20. As a 视频制作者, I want 校验器在没有辅助技能时也能使用本地 ffmpeg 工具, so that 基础验收可独立执行。
21. As a 视频制作者, I want 实际解码错误、非法时长和音画时长不符被拦截, so that 损坏成片不能标记成功。
22. As a 视频制作者, I want 区分检查通过、失败、跳过和未执行, so that 汇报不会把没有验证说成通过。
23. As a 视频制作者, I want G5 强制关联完整成片与技术证据, so that 任意说明文件不能代替交付验收。
24. As a 视频制作者, I want 修改成片后原 G5 自动失效, so that 交付总能指向我实际看过的版本。
25. As a 教学设计者, I want 根据知识关系选择画面与出现顺序, so that 视频不是只会换颜色的文字卡片。
26. As a 教学设计者, I want 仅在明确选择教学模式时校验练习与揭晓结构, so that 科普、推导和原声视频不被强制改成题型微课。
27. As a Agent 操作者, I want 现有 CLI 与自定义命令入口消费相同的制作约束, so that 换入口不会遗漏关键检查。
28. As a 项目维护者, I want 离线回归测试覆盖改稿后的连续两次制作, so that 测试不仅证明首次拦截有效。
29. As a 项目维护者, I want 旧项目获得明确迁移提示且原产物被保留, so that 升级不会静默删除用户材料。
30. As a 视频制作者, I want 失败报告包含阶段和定位信息但不泄露密钥, so that 我可以安全地提交问题。
31. As a 教学设计者, I want 在讲稿中分开描述教学角色、画面形式和视觉主题, so that 换颜色不会冒充教学表达改进。
32. As a 学习者, I want 思考停顿期间画面保持题目状态且答案不提前出现, so that 我能真正独立作答。
33. As a 视频制作者, I want 停顿和尾垫进入实际音轨并按帧边界补齐, so that 视频不会提前结束或裁掉旁白尾音。
34. As a 视频制作者, I want 画板预检失败时配音调用数为零, so that 制作顺序可以被验证而非只靠承诺。
35. As a 项目维护者, I want 关键文档承诺与制作行为共同受测试保护, so that Agent 不会依照过时文档误用入口。
36. As a 教学设计者, I want 画面文字与口播文本在预处理时分别保留教学含义, so that 程序标识符或公式不会为配音方便而被错误改写上屏。

## Implementation Decisions

以下均是待实现决策，不是当前运行能力描述。

### 1. 保留的边界与术语

- 沿用“拍”“region”“cue”“归属检查”“单拍样片”“全量渲染”“成片”和 G0–G5，不引入第二套页面模型。
- 人工确认回答“用户是否同意”；技术检查回答“产物是否符合约束”。两者独立记录，互相不能代替。
- 不以文件名存在、用户说继续、文件哈希未变中的任何一项，单独推导技术验收通过。
- “运行清单”是一次制作实际输入、配置、产物及检查结果的声明；“缓存”只是可复用的候选产物。

### 2. 有效配置与单一校验规则

- 先解析 CLI、环境变量与输入默认值，产生最终有效配置；审批、制作、缓存和校验只消费这一结果。
- 配音有效配置必须包含后端、模型、音色、语速及文本预处理版本。普通版和快速版不能使用同一审批却隐式采用不同语速。
- 渲染有效配置必须包含主题、画幅、fps、质量、绘制与时间窗策略，以及实现和引擎版本。
- 统一验证输入结构、拍标识唯一性、box 范围、有限正时长、cue 顺序与边界；具体容错规则保持与引擎契约一致。
- 复用现有归属检查，不重写一套近似算法。无 region 的均分模式须显式标识，不误判为“归属通过”。
- 静态 CLI 和实际制作入口消费同一套规则，避免手动校验通过而正式入口采用另一套默认值。

### 3. 内容寻址缓存

- 配音合成键包含最终提交给 TTS 的文本、后端、模型、音色、语速及合成契约版本。
- 音频加工键另外包含裁静音、编码和相关时间参数。实现阶段先明确后端语速是在合成期还是加工期生效，纳入对应键。
- 旁白与间隔分离；间隔时长变化应更新间隔及拼接结果，不重复合成语义和合成参数未变的旁白。
- 命中要求：指纹一致、版本一致、产物完整、必要元数据齐全、媒体可验证。无元数据的旧缓存一律视为未命中。
- 视频分拍键包含画板与音轨内容指纹、cue、有效渲染配置、引擎和实现指纹，不再按拍名直接跳过。
- 临时产物验证后再原子落位；中断产物不能发布为有效缓存。不自动删除或截断用户既有文件。

### 4. 本次运行归属

- 以输入字节、有效配置、引用素材和实现指纹生成确定性运行标识；不以时间最新或目录同名判断归属。
- 单拍与全量使用同一完整方案快照；单拍选择仅标记此次执行覆盖的拍，不伪装成全量完成。
- 运行清单使用版本化结构，记录运行标识、阶段、输入指纹、引用素材、实际音轨、分拍、成片、期望时长、生成/复用事实及检查证据。
- 相对路径以清单所在项目为基准；外部路径必须显式声明，不能依赖调用时工作目录猜测。
- 缺失、损坏、版本不支持或指纹不符时停止，不回退扫描旧目录寻找替代品。
- 不同运行的临时产物隔离；同一输出目标冲突时拒绝无提示覆盖，不自动清理历史成片。

### 5. G3、G4、G5 的证据闭环

- G3 绑定当前旁白与有效合成配置。重新确认后仅失效受影响的下游审批，缓存是否可复用仍独立按内容判定。
- G4 要求完整方案快照、当前运行的单拍样片、抽帧及适用的前置检查结果，并记录此次样片覆盖范围。
- 全量渲染必须匹配 G4 的有效配置和完整方案，不能通过更换主题、质量或环境默认值继续沿用确认。
- G5 要求当前完整视频、完整运行清单、必要技术检查通过及用户对当前版本的确认，缺一即停止。
- G5 不接受任意说明文件代替机器检查结果，也不根据视频扩展名单独判定可交付。
- 审批状态需版本化；旧记录不能自动升级成拥有样片或验收证据的新记录。
- 用户可以明确豁免人工观看或选择步骤，但不得豁免必要的媒体完整性与版本一致性检查。
- 审批写入使用唯一临时件与并发保护；避免并行确认覆盖彼此的有效记录。

### 6. 本地预检、技术验收与状态

- G0 的环境预检只检查选用能力的本地条件：解释器、依赖、字体、编码器和配置是否存在；不打印密钥值。
- 联网探测、试听与收费调用继续要求单独授权。存在密钥不能宣称接口连通性已验证。
- 绘图后、批量配音前检查可静态确定的问题；配音后、渲染前检查真实音轨与 cue。
- 媒体校验优先复用现有能力，增加本地 ffprobe/ffmpeg 路线，使基础校验不强依赖仓库外技能。
- 时长必须为有限正数。必要验收包括流信息、完整解码和实际音视频时长，不能以元数据读取成功冒充完整解码。
- 当前成片预期时长以本次实际音轨、静音及明确的时长覆盖规则推导。具体容差由 fps、编码和拼接误差定义并测试，不照搬另一项目的百分比。
- 单项检查使用 PASS、FAIL、SKIP、NOTRUN，并附运行标识、检查方法和证据。缺少结果默认 NOTRUN。
- 必选检查的 FAIL 或 NOTRUN 都阻止“技术验收通过”；SKIP 仅适用于已声明的不适用项。
- 流程入口按预检、样片、渲染、验收阶段短路失败；保留现有 CLI，不先引入多 Agent 调度系统。

### 7. 教学能力按需吸收

- 借鉴“关系、操作、纠错”的画面设计原则，在讲稿确认时描述对象、变化与出现顺序；不把换皮当作信息表达变化。
- 讲稿的每拍计划区分教学角色、画面形式、对象、动作或关系、结果与出现顺序。只有适合知识内容时才使用结构图、步骤或纠错对照，不为追求形式数量强行拆解。
- 教学角色负责这拍的学习目的，画面形式负责如何表达知识关系，主题负责颜色和字体。三者分别建模，不把主题名当作教学模式。
- 教学角色注册表可以集中保存角色约束，但不为所有绘图组件建立未经证明有必要的大型注册表。
- 教学弧是显式可选模式；默认不强制所有视频具备 practice、answer。
- 可选教学模式中的练习停顿采用明确的 hold 时长，进入实际音轨、cue 和总时长计算；不能仅增加画面等待或把“想五秒”读进旁白。
- 音频按实际样本数确定时长，按 fps 向上取整覆盖全部旁白样本；帧边界不足时补静音，不裁掉语音。停顿与尾垫期间冻结对应末态，下一拍揭晓不能提前出现。
- 原始合成音频可共享，追加 hold、裁静音及锁帧后的音轨归当前运行；仅改变 hold 或 fps 时不得再次请求相同旁白的 TTS。
- 画面文本与实际口播文本分别保留。只在 TTS 输入端应用已确认的读法预处理，缓存按实际提交文本判定，不修改源讲稿的标识符或公式含义。
- 本轮可靠性闭环完成前，不开展绘图组件重构和新的教学页面体系。

### 8. 关键文档契约

- 对用户确认顺序、缓存失效维度、运行清单缺失处理、参数约束和预览复用条件建立小范围文档契约测试。
- 同一测试既核对关键承诺已写明，也构造输入证明实际行为符合承诺；不能只匹配固定句子或检查内部注释。
- 不锁定整篇文案、排版或段落顺序；普通措辞调整不应导致无意义测试失败。
- 当实际能力尚未实现或不适用时，文档与检查结果都保留限制，不以修改文案掩盖行为缺口。

### 9. 实施顺序与完成边界

| 工作包 | 优先级 | 前置 | 交付边界 |
|---|---|---|---|
| W1 有效配置与失效规则 | P1 | 无 | 统一合成/渲染配置，定义输入快照和新旧记录迁移 |
| W2 配音缓存正确性 | P1 | W1 | 改稿/换声/调速正确失效，未变旁白可复用，保留旧产物 |
| W3 运行清单与视频缓存 | P1 | W1 | 分拍不再按文件名盲复用，清单精确描述本次实际产物 |
| W4 审批与验收闭环 | P1 | W2、W3 | 前置检查接入制作入口，G4/G5 消费当前证据 |
| W5 状态与离线验收 | P1 | W4 | 四态结果、零配音前置拦截、连续重跑回归、文档契约与迁移说明 |
| W6 教学设计与停顿 | P2 | W5 | 明确画面计划；可选教学模式支持真实静音停顿、锁帧与防提前揭晓，不新增题型渲染后端 |

每个工作包都须有行为测试。W5 是跨包验收，不是允许 W1–W4 延迟补测试。

## Testing Decisions

### 测试边界

首选唯一的高层边界：现有制作 CLI 的可观察行为。
测试输入是一份临时项目及其审批；输出是退出码、阶段状态、审批有效性、缓存事实与交付产物。
TTS 和渲染引擎使用可计数的替身，不在默认测试中访问真实服务。
不为模块私有函数、内部调用次数或注册表具体实现建立脆弱断言。
替身的服务调用计数仅用于判断用户承诺的“是否重新收费合成”，不是锁定内部方法结构。

现有审批测试已经使用临时目录、替换输入确认和 CLI 子进程，继续沿用。
当前 15 项测试保留并扩展，尤其增加“制作一次、改变输入、再次制作”的连续行为测试。
如果跨进程注入替身困难，测试进程内调用同一 CLI main 并替换外部依赖，不增加生产环境的任意命令执行后门。
纯标准库的指纹和清单模块可以补少量单元测试，但不能替代 CLI 验收。

该测试边界已在本轮工作说明中提出；不将用户没有单独回复测试问题解释为已经逐项认可实现细节。按“不采访”要求继续综合并发布规格，若实施必须改变测试边界，再说明原因。

被覆盖的模块包括有效配置解析、审批、缓存、运行清单、配音和渲染编排、媒体校验，以及新增教学模式的时间计算。
默认仍从制作 CLI 验证这些模块的组合行为，不为每个模块增加一套端到端入口。
先例包括现有审批 CLI 测试，以及 eggram 的预览失败零配音、raw/加工音轨分离、并行运行归属与文档契约测试；来源列于 Further Notes。

### 必须覆盖的验收场景

| 编号 | 操作 | 可观察通过条件 |
|---|---|---|
| AC01 | 缺审批启动真实制作 | 非零退出，无制作副作用，不删除旧缓存 |
| AC02 | 同稿同配置连续配音两次 | 第二次合成调用为零，清单如实记录复用 |
| AC03 | 改一条旁白并重新确认 | 只重配受影响片段，成片不引用旧旁白 |
| AC04 | 改后端、模型、音色或合成语速 | 对应缓存失效，旁白清单与新参数一致 |
| AC05 | 只改 gap、裁静音或加工参数 | 按阶段更新，不误复用加工件，不额外合成未变旁白 |
| AC06 | 留下零字节文件、无元数据件或写入中断件 | 不能命中；旧用户文件不被无提示删除 |
| AC07 | 改画板、音轨、cue 或时长覆盖 | 对应视频分拍重渲；其余合法缓存可复用 |
| AC08 | 改主题、质量或实现版本 | 不复用不匹配视频，不沿用旧配置的 G4 |
| AC09 | 新运行缺少、损坏或拿错清单 | 非零退出，不搜索最近目录冒充当前运行 |
| AC10 | 用任意文本代替 G4 样片或 G5 证据 | 审批或交付检查拒绝，说明缺少的证据类型 |
| AC11 | 确认后更改视频、配置或技术报告 | 当前相关确认失效，交付被拦截 |
| AC12 | 归属检查失败或 cue 非法 | 在进入相应后续制作阶段前停止，并报告拍/region |
| AC13 | 仓库外辅助技能缺失 | 仍可用本地媒体工具校验；工具也缺失时清晰阻塞 |
| AC14 | 解码失败、空流、零/NaN/无限时长 | 技术检查失败，不接受为成片 |
| AC15 | 时长超出约定容差 | 技术检查失败，报告实际与期望时长及依据 |
| AC16 | 前置阶段失败 | 后续阶段不执行，其检查为 NOTRUN，不记 PASS |
| AC17 | 两个主题或项目同时执行 | 运行产物不串用；同输出目标冲突明确报错 |
| AC18 | 旧审批或旧缓存迁移 | 明确要求重新确认/生成，不自动删除、不伪造新证据 |
| AC19 | dry-run 或本地环境预检 | 无 TTS、无网络、无配音/视频产物、无密钥泄露 |
| AC20 | 单句试听与完整配音 | 试听受单独授权和文本范围限制，不通过 G3 或代替完整配音 |
| AC21 | 选择非教学模式或无 region 模式 | 不强制练习页；不适用检查有明确状态和原因 |
| AC22 | 完整解码通过但内容尚未人工确认 | 技术通过与 G5 待确认同时保留，不宣称人工验收完成 |
| AC23 | 画板或输入预检失败后请求制作 | 返回对应阶段失败；本地替身 TTS 接收请求数为零 |
| AC24 | 教学模式分别使用 0 秒和 5 秒 hold | 实际音轨与帧数覆盖全部旁白和停顿，帧边界补齐不足一帧，停顿无口播且冻结画面 |
| AC25 | 同旁白只改 hold 或 fps 后重跑 | raw 合成可复用，加工音轨与运行清单更新；不引用另一运行的时间结果 |
| AC26 | 缓存文件元数据匹配但内容无法解码 | 判为不可复用，不以元数据一致代替完整性验证 |
| AC27 | 关键文档仍宣称已删除的回退或错误的缓存维度 | 文档契约测试失败；修正后验证对应 CLI 行为仍成立 |
| AC28 | 教学模式的题目停顿接下一拍答案 | 在题目和停顿时间窗抽帧均无答案；答案只在指定揭晓窗口出现 |
| AC29 | 教学画面包含下划线标识符或公式 | 画面保留原含义，TTS 替身接收确认后的口播版本，缓存按实际口播判定 |

时间窗行为需另以本地可控图形夹具抽帧验证：窗口前无新增目标笔画，窗口内出现目标笔画，窗口结束后目标内容完整。
该测试不调用生图/TTS，也不把“生成了一个大文件”当作对齐正确。
真实中文发音、画面可读性和观看体验保留人工验收；未执行时如实记录。

## Out of Scope

- 不替换白板渲染引擎，不改成 HTML 幻灯片或通用视频生成模型。
- 不引入远程任务队列、多 Agent 并行调度、数据库、云缓存或新的付费供应商。
- 不重构全部绘图组件，不照搬 eggram 的 HTML 溢出选择器和浏览器依赖。
- 不对所有视频强制固定教学弧，不在可靠性改造中新增完整题型页面系统。
- 不把本地审批升级为身份认证或防篡改安全系统；可编辑代码或审批文件的人仍可绕过。
- 不声称哈希、技术检查或对话中的确认原话可以证明用户实际观看了视频。
- 不静默清理旧素材、缓存、虚拟环境或历史成片，不借本任务批量安装依赖。
- 本规格不包含自动开启 GitHub Issues、创建标签或向其他仓库发布需求。
